# BUG-001 메인 메뉴 버튼과 대화상자 입력 필드에 접근 가능한 이름이 없음

| 항목 | 내용 |
| --- | --- |
| 상태 | 업스트림 미수정(기존 이슈 있음, 일부는 초안만 작성) |
| 심각도 | Major |
| 우선순위 | P2 |
| 발견일 | 2026-10-30 |
| 발견 테스트 | `tests/e2e/a11y.spec.ts` (axe `button-name`, `label` 규칙) |

## 환경

- Excalidraw `v0.18.1` 프로덕션 빌드(`vite preview`), Windows 11
- Playwright 1.64.1: Chromium 156.0.8078.4, Firefox 157.0, WebKit 27.2
- 뷰포트 1280x720(데스크톱), Pixel 7(모바일)에서 모두 재현

## 재현 순서

1. 앱을 연다.
2. 스크린 리더(또는 axe)로 왼쪽 위 메뉴 버튼(햄버거 아이콘)을 확인한다.
3. 메뉴 > Save to... 를 열어 "File name" 입력 필드를 확인한다.
4. 메뉴 > Export image... 를 열어 파일명 입력 필드와 Scale(1x, 2x, 3x) 라디오를 확인한다.
5. Save to... > Export to Link 후 나오는 공유 링크 입력 필드를 확인한다.

## 기대 결과

모든 컨트롤이 역할과 이름을 갖는다(예: "Menu" 버튼, "File name" 입력, "1x" 라디오). WCAG 2.1 4.1.2(이름, 역할, 값), 1.3.1.

## 실제 결과

| 컨트롤 | axe 규칙 | 영향도 | 선택자 |
| --- | --- | --- | --- |
| 메인 메뉴 버튼 | `button-name` | critical | `.main-menu-trigger` |
| 저장 대화상자 파일명 | `label` | critical | `#<id>-filename` |
| 내보내기 대화상자 파일명 | `label` | critical | `.TextInput` |
| 내보내기 배율 라디오 3개 | `label` | critical | `input[name="exportScale"]` |
| 공유 링크 입력 | `label` | critical | `input[readonly]` |

Chromium 접근성 트리(CDP `Accessibility.getFullAXTree`)에서도 메뉴 버튼 이름이 빈 문자열입니다. 공유 링크 입력 옆에 "Link"라는 글자가 보이지만 `<label>`로 연결되어 있지 않습니다.

## 영향 범위

스크린 리더 사용자는 메뉴 버튼이 무엇인지 알 수 없습니다. 열기, 저장, 내보내기, 초기화 같은 주요 기능이 모두 이 메뉴 안에 있습니다. 대화상자 입력 필드도 무엇을 입력하는지 읽히지 않습니다. 데스크톱과 모바일 모두 해당됩니다.

## 업스트림 이슈

- 메뉴 버튼: 이미 보고됨. [#11297 a11y: no accesible label for main menu button](https://github.com/excalidraw/excalidraw/issues/11297)(open), 수정 PR [#11300](https://github.com/excalidraw/excalidraw/pull/11300)(open, 2026-10-30 기준 미병합). Deque 감사 이슈 [#7492](https://github.com/excalidraw/excalidraw/issues/7492)의 Issue 8도 같은 버튼입니다.
- 입력 필드 이름(파일명, 배율, 공유 링크): 같은 이슈를 찾지 못했습니다(검색어: "export dialog filename label", "axe label form element", "accessibility screen reader label"). 아래 초안만 작성하고 올리지 않았습니다.
- 참고: 대화상자 자체에 이름이 없는 문제(`aria-labelledby`가 존재하지 않는 id를 가리킴)도 확인했으나 이미 [#11961](https://github.com/excalidraw/excalidraw/issues/11961), PR [#12022](https://github.com/excalidraw/excalidraw/pull/12022)로 보고되어 있어 따로 등록하지 않았습니다.

### 이슈 초안(미등록)

> **a11y: export/save/share dialog inputs have no accessible name**
>
> Version: v0.18.1 (also present on `master` as of 2026-10-30)
>
> axe-core 4.14.0 (`wcag2a`, `wcag2aa`) reports `label` (critical) for:
> - Save to... dialog: file name input (`#<id>-filename`)
> - Export image dialog: file name input (`.TextInput`) and the three `exportScale` radios
> - Shareable link dialog: the read-only URL input (the visible "Link" text is not a `<label>`)
>
> Steps: open each dialog and run axe, or inspect the accessibility tree. Expected: each control has a name ("File name", "Scale 1×", "Link"). Actual: unnamed.

## 재검증

| 날짜 | 대상 | 방법 | 결과 |
| --- | --- | --- | --- |
| 2026-10-30 | 업스트림 `master` | `MainMenu.tsx` 원본 확인 | 트리거에 `aria-label` 없음, 미수정 |
| 2026-10-30 | 로컬 패치 `patches/BUG-001.patch`(메뉴 버튼에 `aria-label`, `title` 추가) | 패치 적용 후 빌드, 같은 테스트 실행 | Chromium, Firefox, WebKit 모두 "Expected to fail, but passed" → 수정 확인 |
| 2026-10-30 | 원본 `v0.18.1`로 되돌림 | 같은 테스트 | 다시 expected fail(결함 재현) |

로컬 패치는 메뉴 버튼만 고칩니다. 입력 필드의 `label` 위반은 그대로라서 `a11y.spec.ts`의 허용 목록에 BUG-001로 남겨 두었습니다.
