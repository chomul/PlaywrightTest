# BUG-002 메뉴의 Open으로 파일을 불러오면 닫혔던 메인 메뉴가 다시 열림

| 항목 | 내용 |
| --- | --- |
| 상태 | 업스트림 미수정(기존 이슈 없음, 초안만 작성) |
| 심각도 | Minor |
| 우선순위 | P3 |
| 발견일 | 2026-10-30 |
| 발견 테스트 | `tests/e2e/happy-path.spec.ts` 작성 중(불러오기 뒤 메뉴 열기가 실패) |

## 환경

- Excalidraw `v0.18.1` 프로덕션 빌드(`vite preview`), Windows 11
- Playwright 1.64.1: Chromium 156.0.8078.4, Firefox 157.0, WebKit 27.2, 뷰포트 1280x720
- 3개 브라우저 모두 재현

## 재현 순서

1. 앱을 연다.
2. 왼쪽 위 메뉴 버튼 > Open을 누른다(메뉴가 닫히고 파일 선택 창이 뜬다).
3. 정상 `.excalidraw` 파일(`tests/data/valid-scene.excalidraw`)을 고른다.

## 기대 결과

장면이 불러와지고 메뉴는 닫힌 상태로 남는다.

## 실제 결과

장면이 불러와진 직후 메인 메뉴가 다시 열린다. 사용자가 메뉴 버튼을 누르면 메뉴가 닫힌다(열려 있는 줄 모르고 누르면 반대로 동작).
깨진 파일을 골라 오류가 나는 경우에도 오류 대화상자 뒤에서 메뉴가 다시 열린다.

## 원인(코드 분석)

`packages/excalidraw/actions/actionExport.tsx`의 `actionLoadScene.perform`은 메뉴가 열려 있던 시점의 `appState`(`openMenu: "canvas"`)를 받아 비동기로 파일을 고른 뒤, 그 `appState`를 바탕으로 결과를 돌려줍니다. 성공(`loadFromJSON(appState, …)`)과 실패(`{ ...appState, errorMessage }`) 모두 메뉴가 열린 상태를 다시 적용합니다.
단축키 Ctrl+O로 열면 메뉴가 열려 있지 않아서 재현되지 않습니다.

## 영향 범위

메뉴의 Open을 쓰는 모든 사용자. 데이터 손실은 없지만, 불러온 그림 일부를 메뉴가 가리고, 메뉴 버튼 토글이 사용자의 예상과 반대로 동작합니다. 오류 경로에서는 BUG-003과 겹쳐서 Escape 처리를 더 어렵게 만듭니다.

## 업스트림 이슈

같은 이슈를 찾지 못했습니다(검색어: "menu open file reopens", "main menu stays open after load", "menu reopens", "menu load open after"). 아래 초안만 작성하고 올리지 않았습니다.

### 이슈 초안(미등록)

> **Main menu reopens after loading a file via Menu → Open**
>
> Version: v0.18.1 (same code on `master` as of 2026-10-30). Chromium, Firefox, WebKit.
>
> Steps: Menu → Open → pick a valid `.excalidraw` file.
> Expected: the scene loads and the menu stays closed.
> Actual: the menu opens again once the scene is loaded. Also happens when the file is invalid (menu reopens behind the error dialog). Ctrl+O is not affected.
>
> Cause: `actionLoadScene.perform` receives `appState` while `openMenu === "canvas"`, awaits the file picker, then returns `loadFromJSON(appState, …)` / `{ ...appState, errorMessage }`, restoring the stale `openMenu`. Resetting `openMenu: null` in both branches fixes it (patch attached).
