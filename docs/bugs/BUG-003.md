# BUG-003 데스크톱에서 오류 대화상자를 키보드(Escape)로 닫을 수 없음

| 항목 | 내용 |
| --- | --- |
| 상태 | 업스트림 미수정(과거 수정 이슈의 회귀로 보임, 초안만 작성) |
| 심각도 | Major |
| 우선순위 | P2 |
| 발견일 | 2026-10-30 |
| 발견 테스트 | `tests/e2e/error-paths.spec.ts` 작성 중(Escape로 닫는 단계가 실패) |

## 환경

- Excalidraw `v0.18.1` 프로덕션 빌드(`vite preview`), Windows 11
- Playwright 1.64.1: Chromium 156.0.8078.4, Firefox 157.0, WebKit 27.2, 뷰포트 1280x720
- 데스크톱 3개 브라우저 모두 재현. 모바일(Pixel 7)은 전체 화면 대화상자에 Close 버튼이 있어 해당 없음

## 재현 순서

1. 앱을 연다.
2. Ctrl+O를 누르고 깨진 JSON 파일(`tests/data/broken.excalidraw`)을 고른다.
3. "Error / Error: invalid file" 대화상자가 뜬다.
4. Escape를 누른다.
5. Tab을 여러 번 누른 뒤 다시 Escape를 누른다.

## 기대 결과

Escape로 대화상자가 닫힌다. 대화상자가 열려 있는 동안 포커스는 대화상자 안에 머문다(WCAG 2.1.1 키보드, 2.4.3 포커스 순서).

## 실제 결과

- 4단계: 대화상자가 그대로 남는다.
- 5단계: Tab이 대화상자 뒤의 툴바 라디오로 이동하고(`aria-modal="true"`인데도), Escape는 여전히 동작하지 않는다.
- 대화상자 바깥을 마우스로 클릭해야만 닫힌다. 데스크톱 오류 대화상자에는 닫기 버튼도 없다.

## 원인(코드 분석)

- `Modal.tsx`는 Escape를 모달 요소의 `onKeyDown`에서만 처리합니다. 포커스가 모달 안에 있어야 동작합니다.
- `Dialog.tsx`는 열릴 때 대화상자 안의 포커스 가능한 요소에 포커스를 줍니다. 그러나 닫기 버튼은 전체 화면(모바일)일 때만 렌더링되고, 오류 대화상자는 글자만 있어서 포커스할 요소가 없습니다. 그래서 포커스가 대화상자 밖에 남습니다.
- 메뉴의 Open으로 열었을 때는 BUG-002 때문에 메뉴까지 다시 열려 Escape가 메뉴 쪽에서 소비됩니다. 이 영향을 빼려고 재현 테스트는 Ctrl+O 경로를 씁니다.

## 영향 범위

키보드만 쓰는 사용자와 스크린 리더 사용자. 잘못된 파일을 열거나 내보내기와 공유가 실패하는 모든 오류 안내에서, 마우스 없이는 대화상자를 닫을 수 없어 작업을 이어갈 수 없습니다.

## 업스트림 이슈

열린 이슈는 찾지 못했습니다(검색어: "error dialog escape", "dialog keyboard close escape", "escape dialog close keyboard", "error dialog focus").
[#1236 Close any dialog with ESC](https://github.com/excalidraw/excalidraw/issues/1236)(2020-04-23 닫힘)이 바로 "잘못된 JSON 파일로 띄운 오류 대화상자"를 Escape로 닫게 해 달라는 이슈였으므로, 현재 동작은 그 수정의 회귀로 보입니다. 아래 초안만 작성하고 올리지 않았습니다.

### 이슈 초안(미등록)

> **Regression of #1236: desktop error dialog cannot be closed with Escape**
>
> Version: v0.18.1 (same `Dialog`/`Modal` code on `master` as of 2026-10-30). Chromium, Firefox, WebKit, desktop viewport.
>
> Steps: press Ctrl+O, choose an invalid JSON file → "Error: invalid file" dialog. Press Escape.
> Expected: dialog closes (as fixed in #1236).
> Actual: nothing happens. Tab moves focus behind the modal; only a mouse click outside closes it.
>
> Cause: `Modal` handles Escape in its own `onKeyDown`, so focus must be inside. `Dialog` focuses the first focusable element on mount, but the close button only renders when `isFullscreen` (mobile) and `ErrorDialog` has no other focusable content, so focus stays outside. Focusing `.Modal__content` (already `tabIndex=0`) when nothing else is focusable fixes it (patch attached).
