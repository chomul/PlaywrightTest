# 테스트 계획: Excalidraw v0.18.1 E2E

## 1. 대상과 환경

| 항목 | 내용 |
| --- | --- |
| 대상 | Excalidraw 웹 앱(`excalidraw-app`), 태그 `v0.18.1` 프로덕션 빌드 |
| 실행 | `vite preview` (http://localhost:4173), Playwright `webServer`로 자동 실행 |
| 브라우저 | Chromium, Firefox, WebKit(데스크톱 1280x720), Pixel 7 모바일 뷰포트(Chromium) |
| 외부 요청 | 모두 `page.route`로 처리. 폰트 CDN은 빌드에 들어 있는 같은 woff2 파일로 응답, 분석 스크립트는 차단, 공유 링크 백엔드는 시나리오별 목 응답 |
| 격리 | 테스트마다 새 브라우저 컨텍스트(빈 localStorage, IndexedDB), 서비스 워커 차단 |

## 2. 우선순위 기준

사용자 영향 기준으로 정합니다.

- **P1**: 실패하면 작업물이 사라지거나 그림을 그릴 수 없음(데이터 손실, 핵심 기능 불가)
- **P2**: 핵심 작업은 되지만 결과물 품질이나 공유, 특정 기기 사용에 문제가 생김
- **P3**: 대체 경로가 있는 편의 기능

파일은 분류별로 나눴습니다(`tests/e2e/`).

| 분류 | 파일 | 시나리오 |
| --- | --- | --- |
| 정상 흐름 | `happy-path.spec.ts` | S1, S3, S4, S6, S7 |

| 오류 경로 | `error-paths.spec.ts` | S5, S6, S7 |

케이스별 목록과 결과는 각 spec 파일의 `test.describe`, `test` 제목과 HTML 리포트에서 확인합니다.

## 5. 검증 방법

캔버스 안의 도형은 DOM 요소가 아니어서 로케이터로 잡을 수 없습니다. 그래서 검증 대상을 나눴습니다.

1. 툴바, 메뉴, 대화상자, 속성 패널: `getByRole`, `getByLabel`, `getByText` 우선. 접근 가능한 이름이 없는 컨트롤(선 굵기 라디오 등)만 앱에 이미 있는 `data-testid`를 씁니다.
2. 캔버스 결과: localStorage `excalidraw` 키의 요소 JSON, 내보낸 `.excalidraw`, PNG, SVG 파일 내용, `toHaveScreenshot`.
3. 대기: `waitForTimeout`을 쓰지 않습니다. localStorage는 `expect.poll`, 화면은 web-first assertion으로 기다립니다.

Chromium은 File System Access API(`showSaveFilePicker`)가 있어서 저장할 때 OS 파일 대화상자가 뜹니다. Playwright가 다룰 수 없으므로 테스트에서는 이 API를 지워서 앱의 대체 경로(`<a download>`, `<input type=file>`)를 쓰게 합니다. Firefox와 WebKit은 원래 이 대체 경로를 씁니다.

## 6. 범위에서 뺀 것

| 항목 | 이유 |
| --- | --- |
| 라이브 협업(실시간 공유) | 지시에 따라 제외. WebSocket 협업 서버와 Firebase가 필요 |
| Excalidraw+ 로그인, 클라우드 저장 | 외부 유료 서비스, 로컬에서 재현 불가 |
| AI 기능(텍스트로 다이어그램 등) | 외부 AI 백엔드 필요 |
| 라이브러리 브라우저(libraries.excalidraw.com) | 외부 사이트 탐색이 핵심이라 목킹 대비 얻는 것이 적음 |
| 이미지 삽입 | 파일 크기, 형식 조합이 넓어 이틀 일정에 맞지 않음. 다음 우선순위 후보 |
| 클립보드 복사, 붙여넣기 | 브라우저별 권한 모델이 달라 헤드리스에서 안정적으로 검증하기 어려움 |
| 다국어 전환 | P3. 문자열 번역 품질은 E2E보다 리뷰가 적합 |
| 성능, 부하 | 이번 목표(E2E와 CI) 밖 |
| 실제 모바일 기기, 터치 제스처(핀치 줌) | 에뮬레이션 뷰포트로만 확인. 실기기 검증은 별도 |

## 7. 종료 기준

- 계획한 테스트가 4개 프로젝트에서 모두 실행됨
- 실패는 앱 결함(→ `docs/bugs/`) 또는 테스트 결함(→ 수정)으로 분류됨
- `--repeat-each=10`에서 flaky 원인을 기록하고 조치함(`docs/FLAKY.md`)
